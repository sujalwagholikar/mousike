# Mousiké 3.6.0 — original Android source

This is the complete original Kotlin/Jetpack Compose project used for the supplied **Mousiké 3.6.0** development APK, updated from the working Mousike 3.5.1 codebase. It is not decompiled or reconstructed source.

## Install the APK

- Android 8 or newer; the supplied APK targets arm64 phones, including the Moto G54.
- Application ID: `com.mousike.app.fast`; version name `3.6.0`, version code `360`.
- Install over the previous Mousike Fast build. Keep the installed app and its data; do not uninstall first if you want to retain your local library.
- The existing development signing key is retained. This is a development distribution, not a Play Store release.

## Build in Android Studio

1. Extract the archive and open the `MousikeNative` directory.
2. Install Android SDK Platform 35 and Build Tools 35.0.0. Select a complete **JDK 17** for Gradle.
3. Let Gradle sync fetch the pinned dependencies. A first build requires internet access; third-party dependency source repositories are not all vendored in this archive.
4. On Linux or macOS run `chmod +x gradlew`, then `./gradlew :app:assembleDebug`.
5. On Windows run `.\gradlew.bat :app:assembleDebug`.
6. The phone APK is `app/build/outputs/apk/debug/app-arm64-v8a-debug.apk`. An x86_64 debug split is also generated by the project for supported environments.

The project pins Gradle 8.13, Android Gradle Plugin 8.13.0, Kotlin 2.1.20, Compose BOM 2025.04.01 and Media3 1.8.0. Minimum API is 26; compile/target API is 35. `local.properties` is deliberately excluded. Android Studio creates it for your local SDK path.

## What is included

- All original application Kotlin code, manifest, XML resources, artwork, app icons, fonts, portrait and original demo audio.
- Gradle build files, wrapper scripts/JAR and the retained development signing key.
- Bundled yt-dlp resource, existing native libc++ binaries, and pinned Android Python/QuickJS/FFmpeg wrapper dependencies.
- Unit and Android instrumentation test source, release notes, architecture, customisation guide, focused validation report and source comparison hashes.
- GPL-3.0 licence and third-party/font notices. See `signing/README.md` before creating a separate production signing identity. The included public development key is not a production secret.

No personal Gemini key is compiled into the project. Users can optionally enter their own key in Settings; Android Keystore encrypts it. The existing configurable Gemini model behaviour is retained, not revalidated as a new model integration in this update.

## Main code paths

| Location | Responsibility |
| --- | --- |
| `app/src/main/java/com/mousike/app/MainActivity.kt` | Compose host, navigation, system insets, refresh-rate policy |
| `ui/screens/` and `ui/components/` | App screens, six font combinations, customisation studio, player presentation |
| `ui/theme/` | Semantic font roles, palette, shape helpers and appearance presets |
| `settings/` | Persisted preferences, encrypted optional API key, quality-selection settings adapter |
| `ui/viewmodel/MousikeViewModel.kt` | Screen state, queue commands, catalog interaction |
| `playback/` | Existing Media3 engine, validated resolution, caching, transport recovery and MediaSession service |
| `data/` | YouTube Music catalog, Room library, metadata persistence and backup codec |
| `recommendation/` | Existing local taste ranker and optional Gemini reranking |
| `album/` | Evidence-based long-recording chapter detection |
| `download/` | Existing WorkManager offline download pipeline |

## Focused checks

Run the selected checks with:

```sh
./gradlew :app:testDebugUnitTest --tests '*QualityAndMusicPreferenceTest' --tests '*AppearancePersistenceTest' --tests '*Stability34Test' --tests '*BufferingWatchdogTest'
```

The source includes additional historical unit and instrumentation suites; older reports and screenshots are retained as history. Only checks explicitly recorded in the current `TEST_REPORT.md` were rerun for 3.6.0. A device playback/visual test is distinct from a successful build or JVM test run.

## Playback preservation

The core engine, source lifecycle, byte-range transport, buffering watchdog, stream validator, cache, notifications and retry policy are unchanged from 3.5.1. Small, isolated changes select the requested quality, prefer music catalog candidates and use a music watch URL in the existing yt-dlp fallback. The current song is not restarted when its quality setting changes. See `validation/changes-360.json` for the file comparison.
