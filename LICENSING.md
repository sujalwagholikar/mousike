## Existing application license

The supplied Android and Windows source trees contain GNU General Public License version 3 text. This pack preserves that text in [LICENSE.md](LICENSE.md). It does not convert GPL-covered code into proprietary, MIT or Apache code.

Read the actual grant in each source file and component. Where a file explicitly says “version 3 or any later version,” preserve that permission. Where it says version 3 only, preserve that restriction. Do not infer or silently rewrite either choice from the presence of the generic GPL text. Before adding SPDX headers, settle the version wording for original files under the owner's authority and preserve all inherited notices.

## What the software license covers

GPL-covered original application source may be used, studied, modified and redistributed under its applicable license. Commercial distribution is not prohibited merely because the app is free to download. Redistributors must follow the actual license conditions, including the applicable source, notice and modification requirements. Do not add a blanket “no copying,” “no modification” or “non-commercial only” restriction to GPL-covered software.

Names, marks, portraits, remote music, lyrics and third-party art require separate consideration. Copyright permission for code does not establish endorsement, publicity rights or permission to use a confusing product identity. Third-party licenses control their own components, including permissive dependencies and fonts.

## Source and binary distribution procedure

1. Identify exactly which source revision produced the binary. Record the commit, platform, architecture, build flags and dependency versions.
2. Preserve existing copyright notices and the full applicable licenses, including dependency-specific notices.
3. Mark modified source and describe changes without misrepresenting upstream authorship.
4. Provide corresponding source in the manner required by the applicable GPL provisions. Include the preferred source form, app build/installation scripts and required material; evaluate Installation Information requirements where applicable.
5. Publish matching source beside the APK/EXE release and retain access to it. A source archive for a different build is not equivalent.
6. For bundled GPL components such as the particular FFmpeg build, arrange an applicable source-distribution method for the exact component, including relevant build configuration. Do not rely solely on a generic upstream link or assume an upstream binary automatically satisfies your obligations.
7. Preserve font licenses, Electron/Chromium notices, GSAP terms and all other upstream notices when distributing their artifacts.
8. Review compatibility before combining new libraries or adopting different distribution terms.
